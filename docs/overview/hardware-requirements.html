Hardware requirements ​

These requirements are only for running a local builtin model — the whole point of which is to work fully offline with nothing leaving your machine.

Dedicated VRAM vs. unified memory ​

OrbySystems sizes its local model against whichever kind of memory your machine actually has available for it:

  • Dedicated VRAM — a discrete GPU (most Windows/Linux gaming and workstation cards). OrbySystems targets your GPU's free VRAM.
  • Unified memory — Apple silicon Macs, and machines without a discrete GPU. OrbySystems targets your machine's free system RAM, since there's no separate VRAM pool.

Either way, OrbySystems detects this automatically and recommends a model size that comfortably fits — you don't need to work out the numbers below yourself. They're here so you know what to expect before you install OrbySystems.

Recommended: the 4B model at 64k context ​

The 4B model at a 64k-token context window is the sweet spot OrbySystems is tuned around — capable enough for real finance reasoning over a long conversation, while still running comfortably on a single consumer GPU or an ordinary laptop's unified memory.

Dedicated VRAMUnified memory (system RAM)
Model weights + context~6 GB~6 GB
Recommended headroom~2 GB~2 GB or more
Target free memory~8 GB~8 GB
Recommended installed memory10-12 GB VRAM card16 GB total system RAM

The "target free memory" row is what is recommended to be available for the model — the last row estimates what the installed memory should be taking into account reasonable overheads. These numbers can change depending upon what else is running on your system and what context size you choose.

Hint: Go to the Settings -> Models page when OrbySystems first starts, it will tell you what GPU/unified device it detects and how much free memory it sees.

The Settings -> Models page will also indicate how much context has been allocated based on the free memory. This can be adjusted via low/medium/high settings on the model card.

The 2B model: supported, not recommended ​

OrbySystems also ships a 2B model. It's supported and will run on much lighter hardware (roughly 4-6 GB of free memory), which makes it a reasonable fallback on an older machine or a memory-constrained VM. It's meaningfully less capable than the 4B model at real finance reasoning, though, so it isn't what OrbySystems recommends by default — treat it as a "this still works" option rather than a target to design around.

Docling (document ingestion) ​

Docling is the local service OrbySystems uses to convert PDFs and other documents into text for ingestion (and to re-read a page's layout when redacting it — see the PII Redactor). It's deliberately CPU-only: on a GPU, its layout/OCR models use a lot of VRAM — worst on image-heavy pages — for little wall-clock gain over CPU, and that VRAM is worth more to your local model. So Docling adds no VRAM requirement, but it does need roughly 4 GB of free system RAM while it's running, on top of whatever your local model needs.

Presidio (PII detection) ​

Presidio is OrbySystems's default engine for detecting personal information — used by the PII Detector and PII Redactor. It's also CPU-only, and needs roughly 1.5 GB of free system RAM while running.

Adding it up ​

Docling and Presidio are both started on demand — they only run (and only use this memory) while you're actually ingesting a document or checking/redacting PII, not for the whole time OrbySystems is open. If you do that alongside chatting with your local model, budget their memory on top of the model's: roughly +4 GB of system RAM while Docling is active, and +1.5 GB of system RAM while Presidio is active — both independent of whether your model itself runs on a dedicated GPU or unified memory, since these two always run on CPU/RAM regardless.

If your hardware falls short ​

Nothing about OrbySystems requires a local model - you can connect to an external model running in the cloud or on a separate machine via a standard API endpoint instead (see Settings → Models). However, OrbySystems operates under the assumption that there is at least one trusted model configured that can be used to chat about your data. Be clear about which LLM services you trust.
